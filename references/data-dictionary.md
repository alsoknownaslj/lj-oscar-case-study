## ccs.csv — ICD-10-CM → multi-level CCS mapping

72,167 rows; `diag` is **unique** (a proper mapping key). 400-row sample committed at
`references/samples/ccs_sample.csv`.

| column | type | notes |
|---|---|---|
| `diag` | str | ICD-10-CM, **undotted**, 3–7 chars, unique (`A000` … `Z9989`) |
| `diag_desc` | str | description; contains commas (quoted in CSV) |
| `ccs_1_desc` | str | level 1 — 18 chapters |
| `ccs_2_desc` | str | level 2 — 135 real values; **a single space `' '` (not `''`) on the 7,621 Residual rows** — strip before testing; ~44% embed a code like `[135.]` |
| `ccs_3_desc` | str | level 3 — 281 values, never blank; often equals level 2 |

Quirks: semicolons replace commas inside descriptions (never split on `;`); the Residual
chapter has no level-2 category — handle explicitly. Note the code *universe* is dominated
by Injury & poisoning (40k of 72k codes) — that says nothing about claim volume.

## claim_lines.csv — diagnoses on claims

1,919,983 rows; `record_id` unique (1…1,919,983); **245,166 distinct members** (`M`-prefixed
strings). One row = one diagnosis × member × service date.

| column | type | notes |
|---|---|---|
| `record_id` | int (load as str ok) | unique row id |
| `member_id` | str | `M0000001` … `M0291613` |
| `date_svc` | date | **24 rows null; 38 stray rows 1899–2014** (sentinel/dirty); real window **2015-09 → 2018-12** (Jan–Aug 2015 holds only ≈160 rows, ramp starts 2015-09, peak 2016) |
| `diag1` | str | ICD-10, **91.9% dotted** (`N92.6`); 63 rows of junk code `000`; 1 row with an embedded comma (`L02.,821`, CSV-quoted); 507 legit undotted >3-char codes |

Join: `normalize_icd10(diag1)` → `ccs.diag` covers **99.89% of rows** (19,845 of 20,062
distinct codes; 217 codes unmapped). The CSV **uses quoted fields** deep into the file —
always parse with `quote='"'` (duckdb's auto-detection sniffs only early rows).

## prescription_drugs.csv — filled prescriptions

3,005,934 rows; `record_id` unique (huge random 63-bit ints — keep as string);
**240,735 distinct members**. One row = one fill.

| column | type | notes |
|---|---|---|
| `record_id` | str | unique, up to 19 digits — never cast to float |
| `member_id` | str | same scheme as claims |
| `date_svc` | date | window **2013-12 → 2018-06**: starts ~2 years before claims ramp up and ends **6 months before claims end** — align windows explicitly when labeling |
| `ndc` | str | all 11-digit, leading zeros present (`00002143301`) |
| `drug_category` | str | 90 values (coarse) |
| `drug_group` | str | 477 values |
| `drug_class` | str | 684 values (primary feature tier) |

## Population overlap

245,166 members in claims, 240,735 in rx, **194,290 in both** — the labeled population for
the rx-only model. ~51k members have claims but no fills; ~46k have fills but no claims
(both groups are findings, not noise: no-rx members still need a predicted status).
